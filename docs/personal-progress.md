# Personal rehabilitation progress

Progress Analytics reuses `GET /api/analytics/rom`, the saved session analytics JSON, and the existing session comparison endpoint. No database migration is required. Optional prescribed rep and excursion targets are recorded at session start, and optional pain and stiffness ratings are recorded at finish. Targets are entered by the user and are not generated by ShoulderSense. Existing scoring models and replay processing are unchanged.

## Measurement contract

- **Median rep excursion** is the median across a session of each completed estimated rep's peak minus its observed starting level. The counter records that level from resting samples before ascent. The median peak angle is also saved separately. The live angle is a calibrated sensor proxy, and may include wrist twist or elbow motion.
- **Rep count and plan** report estimated completed reps and completed ÷ prescribed reps when a target exists. Completion can exceed 100%; it does not feed the score.
- **Control** uses the standard deviations of the rep peaks and durations, along with one jerk metric when available. Mean duration remains a separate measurement. The 50 Hz vector jerk and low-rate acceleration-magnitude jerk are separate measures. Low-rate time-weighted wrist speed uses the existing wrist trace and skips gaps over 1.25 s. Reps must contain at least three usable intervals covering at least 60% of the measured cycle.
- **Torso rotation** is peak chest-sensor orientation change relative to its initial session orientation. It includes motion outside reps and can reflect setup or normal torso movement. It is a posture proxy and cannot determine whether compensation occurred.
- **Symptoms** are optional self-reported pain and stiffness on 0–10 scales. No function score is inferred from these ratings.

## Baseline and compatibility

Progress uses the first three completed live sessions with two or more estimated reps and a recorded neutral capture, sensor device, angle source, measurement method, rep threshold, and counting protocol. Patient, exercise, shoulder side and those protocol fields must match. Legacy sessions without a recorded protocol remain visible as observations. Most legacy sessions saved only the last-three peak summary, so no full-session excursion median is reconstructed. Low-rate motion comparisons additionally require the median stored wrist interval to be within a 1.25× ratio across sessions. A baseline metric must be present on all three anchor sessions; its value is their median. No missing metric is assigned a number.

The latest session shows the current value minus that baseline median in the measurement's units. The charts show the latest three compatible measurements' rolling median. A mobility direction requires three distinct measured days after the last baseline date. All three daily medians must be above the observed baseline range for an improving trend or below it for a declining trend. All three inside the range are labelled stable; mixed results are inconclusive. These descriptive labels have no minimum clinically important difference interpretation.

## Experimental index

The default weights are 40% mobility, 25% control, 15% posture, and 20% symptoms. For available component scores, the index is `sum(weight × component) / sum(available weights)`. Display requires at least two components, including an objective component, and at least 40% of configured weight. The UI labels incomplete coverage as partial.

- **Mobility** uses `min(100, 100 × median rep excursion / prescribed excursion)` when a target is supplied, or `100 × current / (current + baseline)`.
- **Control** averages the available normalized peak variation, duration variation, and a single comparable jerk metric, preferring the 50 Hz measurement.
- **Posture** normalizes peak chest rotation. Control and posture use `100 × baseline / (current + baseline)`.
- **Symptoms** average available `100 − 10 × rating` values. Equal current and baseline values score 50 in the relative formulas, including two measured zeros.

Set `SHOULDERSENSE_PERFORMANCE_WEIGHTS` to a JSON object with positive finite `mobility`, `control`, `posture`, and `symptoms` weights to override the defaults. Weights are normalized to sum to one.

The baseline index is recomputed on the three anchor sessions with the **current score's component inputs and target**, and their median is compared with the current score. If any input is absent in the baseline, index change is unavailable. Daily points use the median of sessions on that UTC day with the same protocol, component inputs and target. Weekly points use the median of those days in Monday-start UTC weeks. The index is calculated on demand and may show scores for the first three days retrospectively, once the baseline has been established. The index expresses measured performance under these assumptions. A smaller chest rotation or lower jerk is not proof of better clinical function; effort, excursion, pace, sensor placement, and sampling can all affect the values.

## SPARS9x contextual distributions

```sh
cd backend
../.venv/bin/python -m app.services.analytics.dataset_reference ../dataset
```

The command uses the existing dataset reader and feature extractor for all ten activity labels across the 20 available participants. It reports 10th percentile, median and 90th percentile across participant medians of 50 Hz wrist speed and jerk features, plus labeled bout duration (which may include pauses). Rep duration and consistency distributions are withheld because candidate segmentation and the small same-phase review do not establish anatomical rep boundaries across all exercises. Replay uses wrist signals and its existing provisional flexion cycles. Chest rotation, anatomical shoulder ROM and patient ratings are unavailable for replay. Contextual ranges are separate from live scoring and targets because sampling, hardware and placement differ.
